Memory Leak Test - Interact.js

This test verifies the memory leak fix for interact.js.

Scenario: The app stores references to Interactable objects and calls unset() on them when done, expecting unset() to clear internal references to DOM elements and allow garbage collection.

The Bug: Before the fix, unset() didn't adequately clear references - it left DOM element references in the Interactable and its associated Interactions, preventing garbage collection even after calling unset().

The Fix: unset() now properly destroys interactions and clears element references, allowing garbage collection even when the app retains references to the Interactable objects.

Instructions:

  1. Open Chrome DevTools (F12) → Memory tab
  2. Take a heap snapshot (baseline)
  3. Click "Create Many Elements" several times (creates 100 each)
  4. Click "Destroy All Elements" (calls unset() but keeps interactable references)
  5. Force garbage collection (DevTools → Performance → 🗑️ icon)
  6. Take another heap snapshot and compare
  7. WITHOUT FIX: You'll see detached DOM nodes (leaked) because unset() didn't clear element references
  8. WITH FIX: DOM nodes are properly freed because unset() now clears all references
  9. Optional: Click "Clear Interactable References" then GC to verify final cleanup

Note: interact.debug() creates 1 interaction on first call (pre-existing behavior).
